\section{Large Language Models}
\label{sec:bg-llm}

\subsection{Transformer Architecture}
\label{sec:bg-transformer}

Modern large language models are based on the Transformer architecture~\cite{vaswani2017attention}. Its central operation is \emph{self-attention}: every token of a sequence is projected into a query $Q$, a key $K$ and a value $V$, and the output for each token is a weighted sum of the values of all tokens, with weights given by the similarity of its query to their keys:
\begin{equation}
    \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V,
\end{equation}
where $d_k$ is the dimension of the keys. Several attention heads run in parallel (multi-head attention), and attention layers alternate with feed-forward layers, residual connections and normalization.

Large language models such as GPT are \emph{decoder-only} Transformers trained for next-token prediction: given the tokens $x_1, \dots, x_{t-1}$, the model outputs a probability distribution $P(x_t \mid x_1, \dots, x_{t-1})$ over the vocabulary, and text is generated by sampling one token at a time. A causal mask keeps each position from attending to later positions. The amount of text the model can attend to at once is bounded by its \emph{context window}.

This project uses LLMs as components through provider APIs and does not train or fine-tune them; the rest of this section covers only the properties that matter for using them.

\subsection{Pre-training, Instruction Tuning and Alignment}
\label{sec:bg-pretraining}

An LLM is first \emph{pre-trained} on a very large text corpus with the next-token objective. At sufficient scale, pre-trained models acquire the ability to perform a task from a description and a few examples given in the prompt, without any update of their weights (\emph{in-context learning})~\cite{brown2020language}. The models used as assistants are then \emph{instruction-tuned} on examples of instructions and good responses, and aligned with human preferences by reinforcement learning from human feedback (RLHF)~\cite{ouyang2022training}. Alignment makes models follow instructions well, but it also makes them agreeable by default: models trained on human preferences tend to tell users what they want to hear (\emph{sycophancy})~\cite{sharma2024sycophancy}, a tendency that the persona agent of the proposed workflow must counter so that simulated stakeholders disagree when their priorities conflict.

\subsection{Prompting Techniques}
\label{sec:bg-prompting}

The behavior of an LLM is controlled by its \emph{prompt}. Chat models receive a \emph{system prompt}, which sets the role and the rules, followed by \emph{user} and \emph{assistant} messages. The main prompting techniques are:
\begin{itemize}
    \item \textbf{Zero-shot prompting}: the task is described without examples.
    \item \textbf{Few-shot prompting}: a few input-output examples are given before the input~\cite{brown2020language}.
    \item \textbf{Role (persona) prompting}: the model is told to act as a given person or expert, which shapes the content and the style of its answers.
    \item \textbf{Chain-of-thought prompting}: the model is asked to reason step by step before answering, which improves multi-step reasoning~\cite{wei2022chain}.
\end{itemize}

When the output of a model is consumed by a program rather than read by a person, it must follow a fixed format. \emph{Structured output} constrains the model to produce JSON that conforms to a given JSON Schema, usually derived from a typed data model. Every agent of the proposed workflow returns structured output, which is validated against the content schema of the items it creates before anything is saved.

\subsection{Tool Use and Retrieval-Augmented Generation}
\label{sec:bg-tools-rag}

An LLM can be given \emph{tools}: functions described by a name, a description and a schema of their arguments. The model decides when to call a tool and with which arguments; the application executes the call and returns the result to the model. ReAct interleaves reasoning steps with such actions and observations, so that the model can gather information before it answers~\cite{yao2023react}.

\emph{Retrieval-augmented generation} (RAG) supplies the model with documents retrieved from an external source at inference time and asks it to answer from them~\cite{lewis2020retrieval}. Grounding generation in retrieved documents reduces unsupported statements and makes the output traceable to its sources. The corpus builder of the proposed workflow follows this principle: it retrieves real documents of the domain through web and academic search, and every later persona is built only from what these documents contain.

\subsection{Limitations of LLMs}
\label{sec:bg-llm-limitations}

Several limitations of LLMs shape the design of the proposed framework:
\begin{itemize}
    \item \textbf{Hallucination}: models produce fluent statements that are not supported by their input. The workflow therefore requires every requirement to carry evidence and every quote to be copied exactly from its source, which the system checks.
    \item \textbf{Bias and homogeneity of generated personas}: personas generated without data tend to be stereotypical, overly positive and similar to each other, and adding generated details can increase rather than reduce the bias~\cite{li2026persona}.
    \item \textbf{Limited persona adherence}: models differ in how consistently they stay in character, and larger models are not necessarily better at it~\cite{samuel2025personagym}.
    \item \textbf{Context length and cost}: every call is billed by the number of input and output tokens. Providers cache a repeated prompt prefix and bill the cached part at a lower price, so the workflow places the fixed part of each prompt first and gives each agent only the artifacts it needs, not the whole history of the run.
    \item \textbf{Non-determinism}: the same prompt can produce different outputs, so experiments must be repeated and their results reported with their variance.
\end{itemize}
