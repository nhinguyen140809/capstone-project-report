\section{User Interface Design}
\label{sec:sd-ui}

The user interface is designed around the review checkpoints: whatever the layout, the user must see what the run is doing, what it waits for and which artifact a decision concerns, without leaving the page (NFR-10). After logging in, the user chooses one of two layouts for the whole application, and can change the choice later in the settings (Figure~\ref{fig:sd-ui-views}).
\begin{itemize}
    \item \textbf{User layout}, labelled \emph{Guided view} in the application. Designed for people who use the system to work on a product. The home page asks for the product idea and lists the projects. The page of a project places the chat with the agents beside a reader that shows the artifact or item the conversation refers to, so that the user can follow the run, answer the reviews and read the results without leaving the page.
    \item \textbf{Developer layout}, labelled \emph{Developer view}. Designed for people who inspect how a run works. Besides the projects and the settings, the page of a project gives access to its activity, to its documents and artifacts, to every item with its content and history, and to the traceability views: the trace of an item, the gaps where a requirement lacks a source or a user story, and the open issues.
\end{itemize}
The settings also let the user choose the theme and the model of each agent role. Table~\ref{tab:sd-screens} lists the main screens and the use cases they serve; the figures that follow were captured from the web application in its mock mode, in which simulated responses with sample data replace the API (Section~\ref{sec:impl-frontend}).

Figure~\ref{fig:sd-ui-review} shows the project page of the user layout while a run waits at the analysis review. The review is rendered from the workflow definition: each option of the checkpoint becomes a choice with its description, and the option that needs feedback asks for it. A message sent while the run waits is shown with the note that it will be read after the review, and the bar under the input shows the progress of the run through its stages.

The trace page (Figure~\ref{fig:sd-ui-trace}) draws the trace graph of an item, from the research document and the stakeholder observation it comes from, through the interviewee and the stated needs, to the requirements and the user stories derived from it. A link made against an older version of its target, or whose target has since been replaced, is marked as out of date, so that the user can check it.
